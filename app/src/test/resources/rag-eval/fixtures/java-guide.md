# Java 后端核心知识手册（测评专用）

本文档为 RAG 测评人工编写的虚构知识库，内容与任何真实项目无关。

## JVM 垃圾回收

JVM 垃圾回收器的发展经历了 Serial、Parallel、CMS、G1、ZGC 几代。G1 回收器把堆划分为多个等大的 Region，默认期望停顿目标是 200 毫秒。ZGC 是面向低延迟的回收器，停顿时间不超过 1 毫秒，支持 TB 级堆。

垃圾回收的判断使用可达性分析算法，从 GC Roots 出发不可达的对象可以被回收。GC Roots 包括虚拟机栈中引用的对象、方法区中类静态属性引用的对象、本地方法栈中 JNI 引用的对象。

对象分配优先在新生代 Eden 区进行，Eden 不足时触发 Minor GC。对象分配优先在新生代 Eden 区进行，Eden 不足时触发 Minor GC；晋升路径的阈值控制见后文 JVM 生产实践章节。

## HashMap 与 ConcurrentHashMap

HashMap 在 JDK 8 之后的底层结构是数组加链表加红黑树，链表与红黑树之间的转换条件见后文集合生产实践章节。

HashMap 的容量总是 2 的整数次幂，这样 hash 值对容量取模可以转化为位运算 `(n - 1) & hash`。默认初始容量是 16，负载因子是 0.75，元素数量超过容量乘以负载因子时触发扩容，扩容为原来的两倍。

ConcurrentHashMap 在 JDK 8 中放弃了分段锁，改用 CAS 加 synchronized 锁住单个桶的头节点。size 统计使用 baseCount 加 CounterCell 分散计数的方式实现。

## 线程池

线程池的核心参数一共有七个：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。任务提交后，线程数小于 corePoolSize 时直接创建核心线程；核心线程满后任务进入工作队列；队列满后创建非核心线程直至 maximumPoolSize；再满则触发拒绝策略。

内置的四种拒绝策略分别是：AbortPolicy 抛出异常、CallerRunsPolicy 由提交线程执行、DiscardPolicy 静默丢弃、DiscardOldestPolicy 丢弃队首最老任务。拒绝策略的选择属于生产实践问题，后文线程池生产实践章节再展开。

线程池的线程数配置没有万能公式。CPU 密集型任务建议线程数等于 CPU 核数加一；IO 密集型任务建议线程数为 CPU 核数乘以二，或按 IO 等待比例用公式核数乘以（一加 IO 时间除以 CPU 时间）估算。

## MySQL 索引

InnoDB 的索引组织结构是 B+ 树，数据行本身存储在主键索引的叶子节点上，这种表称为索引组织表。二级索引的叶子节点存储主键值而不是行地址，因此通过二级索引查询完整行需要回表。

最左前缀原则要求联合索引只能按定义顺序从最左列开始匹配。索引下推是 MySQL 5.6 引入的优化，在存储引擎层先过滤联合索引中包含的条件下推列，减少回表次数。

## Redis 基础

Redis 的持久化方式包括 RDB 快照和 AOF 日志。RDB 是某一时刻的全量二进制快照，恢复快但可能丢失最后一次快照后的数据。AOF 记录每条写命令，通过 appendfsync 策略控制刷盘，策略有 always、everysec、no 三种，默认 everysec 表示每秒刷盘一次。

Redis 单线程处理命令请求，但 IO 读写和网络协议解析在 6.0 之后支持多线程。缓存穿透的常见解决方案是布隆过滤器和空值缓存；缓存击穿的解决方案是互斥锁和逻辑过期；缓存雪崩的解决方案是过期时间加随机偏移和多级缓存。

## Spring 核心

Spring Bean 的生命周期可以概括为：实例化、属性注入、初始化前处理、初始化（InitializingBean 的 afterPropertiesSet 或 init-method）、初始化后处理、使用、销毁。BeanPostProcessor 的 postProcessAfterInitialization 是 AOP 生成代理对象的常见时机。

Spring 事务失效的常见场景包括：同类内部方法调用绕过代理、方法不是 public、异常被 catch 吞掉、默认只回滚 RuntimeException 和 Error。解决办法分别是通过代理对象调用、改用编程式事务、显式回滚或配置 rollbackFor。

Spring Boot 自动装配依靠 `@EnableAutoConfiguration` 导入的自动配置类，配合 `@ConditionalOnClass`、`@ConditionalOnMissingBean` 等条件注解按需生效。自定义 Starter 的关键是把自动配置类注册到 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 文件中。

## 网络与协议

TCP 三次握手的目的是同步双方初始序列号并确认彼此收发能力。TIME_WAIT 状态持续两倍最大报文段寿命，即 2MSL，目的是确保最后一个 ACK 能到达对端并让旧报文在网络中消亡。

HTTP/2 相比 HTTP/1.1 的核心改进是二进制分帧、多路复用、头部压缩 HPACK 和服务器推送。多路复用解决了 HTTP/1.1 队头阻塞在连接层面的问题，但 TCP 层的队头阻塞仍然存在，直到 HTTP/3 换用 QUIC 基于 UDP 才解决。

## 分布式基础

CAP 定理指出分布式系统在一致性、可用性、分区容错性三者中最多同时满足两个。网络分区不可避免，因此实际的取舍是在 CP 和 AP 之间。ZooKeeper 偏向 CP，Eureka 偏向 AP。

分布式锁的常见实现有基于 Redis 的 SET NX EX 和基于 ZooKeeper 的临时顺序节点。Redis 分布式锁的续期问题可以用看门狗机制解决，RedLock 算法因为时钟漂移等问题存在争议，多数业务场景用单实例锁加 fencing token 即可。

## Java 并发：锁与同步

synchronized 修饰实例方法锁的是当前对象，修饰静态方法锁的是类的 Class 对象，修饰代码块可以指定任意对象。JDK 6 之后 synchronized 引入了偏向锁、轻量级锁和重量级锁的升级过程，锁升级的方向不可逆。锁信息存储在对象头的 Mark Word 中。

volatile 关键字有两个语义：保证可见性和禁止指令重排序。禁止重排序是通过内存屏障实现的。经典的 double-checked locking 单例模式中，实例字段必须用 volatile 修饰，防止对象初始化指令重排后其他线程拿到半初始化对象。

AQS 是 J.U.C 的核心框架，内部维护一个 volatile int state 和一个 CLH 变体的双向队列。ReentrantLock 的公平锁通过队列先来后到获取锁，非公平锁允许新线程直接抢锁。独占模式的核心方法是 acquire 和 release，共享模式的核心方法是 acquireShared 和 releaseShared。

ThreadLocal 为每个线程维护独立的变量副本，底层是 Thread 对象里的 ThreadLocalMap，key 是 ThreadLocal 的弱引用，value 是强引用。如果线程池线程长期存活且忘记调用 remove，value 无法回收就会内存泄漏。父线程的 ThreadLocal 值传递给子线程需要 InheritableThreadLocal 或阿里开源的 TransmittableThreadLocal。

CAS 即比较并交换，通过 CPU 的原子指令实现。Java 中通过 Unsafe 类的 compareAndSwap 方法调用。CAS 的三大问题是 ABA 问题、自旋开销和只能保证单个变量的原子性。ABA 问题可以用带版本号的 AtomicStampedReference 解决。

J.U.C 常用同步工具类：CountDownLatch 允许一个线程等待多个线程完成，计数不可重置；CyclicBarrier 让一组线程互相等待到同一个屏障点，可重复使用；Semaphore 控制同时访问资源的线程数；Exchanger 用于两个线程交换数据。CompletableFuture 提供了 thenApply、thenCompose、allOf 等链式编排能力，默认使用 ForkJoinPool 的 commonPool。

## JVM 内存区域与类加载

JVM 运行时数据区分为线程私有的程序计数器、虚拟机栈、本地方法栈，和线程共享的堆、方法区。JDK 8 之后方法区由元空间实现，使用本地内存，字符串常量池早在 JDK 7 就移到了堆中。栈溢出抛 StackOverflowError，堆溢出抛 OutOfMemoryError。

类加载过程包括加载、验证、准备、解析、初始化五个阶段。准备阶段为静态变量分配内存并设零值，初始化阶段才执行类构造器 clinit 赋真实值。双亲委派模型要求子加载器先把请求委托给父加载器，保证核心类库不被篡改。打破双亲委派的常见例子有 SPI 的线程上下文类加载器、热部署以及 OSGi 模块化。

线上 JVM 排查常用命令组合：jps 定位进程，jstat -gcutil 查看各代使用率与 GC 次数，jmap -histo 查看对象直方图，jmap -dump 导出堆快照后用 MAT 分析支配树。Arthas 的 dashboard、thread、jad 命令可以在不重启的情况下动态诊断。

## 集合框架进阶

ArrayList 底层是 Object 数组，默认容量 10，扩容为原来的 1.5 倍。随机访问 O(1)，中间插入删除 O(n)。LinkedList 底层是双向链表，同时实现了 Deque，可以当队列和栈使用，但随机访问是 O(n)，实际工程中很少用它。

LinkedHashMap 在 HashMap 基础上维护了双向链表维护插入顺序或访问顺序。将 accessOrder 设为 true 并重写 removeEldestEntry 即可实现 LRU 缓存，这是面试高频手写题。

fail-fast 机制指迭代器遍历中检测到结构性修改就抛 ConcurrentModificationException，实现原理是比较 modCount。fail-safe 的迭代器遍历的是副本，比如 java.util.concurrent 包下的容器，代价是不能保证读到最新数据且内存开销更大。

## MySQL 进阶

事务的四大特性 ACID 分别依赖 redo log 保证持久性、undo log 保证原子性、锁加 MVCC 保证隔离性。四种隔离级别中，读未提交存在脏读，读已提交解决脏读但存在不可重复读，可重复读是 MySQL 默认级别并通过间隙锁在很大程度上避免幻读，串行化完全加锁。

MVCC 的实现依赖行记录隐藏列 trx_id 和 roll_pointer、undo log 版本链，以及 ReadView 的一致性视图判断。读已提交级别每次查询都生成新的 ReadView，可重复读级别只在第一次查询时生成。

redo log 是物理日志记录页修改，采用 WAL 机制先写日志再刷数据页，保证崩溃恢复；binlog 是逻辑日志用于主从复制和时间点恢复。两阶段提交先写 redo log 处于 prepare 状态，写 binlog 后再 commit，保证两份日志一致。

死锁排查依靠 `SHOW ENGINE INODB STATUS` 中的 LATEST DETECTED DEADLOCK 段。预防手段包括按相同顺序访问资源、小事务、给索引覆盖查询条件避免锁范围放大。

深分页的优化方案：延迟关联先用覆盖索引查出主键再回表，或者用游标方式记录上一页最大 ID 用 where id > lastId limit n。千万级大表建议归档或分表。

## Redis 进阶

Redis 集群方案有三种：主从复制提供读扩展但不自动容错；哨兵在主从基础上增加自动故障转移，哨兵之间通过 raft 选出领导者执行切换；Cluster 模式按 16384 个 hash slot 分片，节点间 gossip 协议通信，客户端智能定向。

Redis 的 zset 底层是 listpack 加 skiplist 的组合，元素较少时用 listpack，增多后转换为跳表。跳表插入删除只需要修改前后指针，比平衡树实现简单且范围查询友好。

大 key 指单个 key 的 value 过大或集合元素过多，删除大 key 会阻塞主线程，应该用 unlink 异步删除或 scan 分批处理。热 key 指单个 key 访问集中，可以用本地缓存扛读或多副本 key 分散。

Redis 分布式限流的常见实现有固定窗口计数器、滑动窗口日志、漏桶和令牌桶。令牌桶允许突发流量，Guava RateLimiter 和 Redis 加 Lua 脚本实现的单机或分布式限流都基于它。

## 网络进阶

HTTPS 的握手流程：客户端发送随机数与加密套件，服务端返回随机数、证书与选择的套件，客户端验证证书后生成预主密钥并用服务端公钥加密发送，双方基于三个随机数生成会话密钥，之后改用对称加密通信。TLS 1.3 把握手压缩到一次往返。

WebSocket 通过 HTTP 101 状态码升级协议，建立全双工连接后用帧格式通信。心跳通过 ping/pong 帧维持，断线重连需要客户端实现退避策略。与 SSE 相比，WebSocket 支持双向，SSE 只支持服务端推送但实现简单且自带重连。

## 分布式进阶

一致性哈希把 hash 空间组织成环，节点和 key 都映射到环上，key 顺时针找第一个节点。引入虚拟节点解决数据倾斜，一个物理节点通常映射一两百个虚拟节点。相比取模分片，节点增减只影响相邻区间的数据。

分布式事务的常见方案：2PC 强一致但同步阻塞且有单点；TCC 通过 try confirm cancel 三个阶段业务补偿；本地消息表依靠本地事务加消息投递保证最终一致；Saga 把长事务拆成一系列本地事务加逆向补偿。电商下单链路多数选择本地消息表或事务消息保证最终一致。

幂等设计的常用手段：唯一索引兜底、token 机制先申请后提交、状态机约束状态流转、乐观锁版本号。幂等键的选择要覆盖业务语义，比如订单号加操作类型。

限流后的熔断与降级：熔断器有三态 closed、open、half-open，失败率超阈值后熔断跳闸，冷却期后半开放行探测请求。Sentinel 和 resilience4j 提供了滑动窗口统计与规则配置的现成实现。

## Spring 进阶

Spring 循环依赖依靠三级缓存解决：一级缓存 singletonObjects 放成品，二级缓存 earlySingletonObjects 放半成品，三级缓存 singletonFactories 放工厂。构造器循环依赖无解，只能改造为 setter 注入或用 @Lazy。AOP 代理在三级缓存的工厂回调中提前生成，保证注入的是最终代理对象。

AOP 的实现是运行时动态代理：目标实现了接口默认用 JDK 动态代理，否则用 CGLIB 子类代理。切面注解 execution 表达式匹配连接点，通知类型有 Before、AfterReturning、AfterThrowing、Around。内部调用不走代理是 AOP 失效的另一个常见原因，与事务失效同类。

Spring 事件机制通过 ApplicationEventPublisher 发布、@EventListener 订阅，默认同步执行，加 @Async 后异步。适合解耦非核心链路，比如下单后发积分、记日志。监听器异常不影响发布方，但异步线程池要有界并配置拒绝策略。

## 设计模式与编码

单例推荐枚举或静态内部类方式，双重检查锁必须加 volatile。策略模式配合 Spring 的 Map 注入可以替代复杂的 if else，把策略 bean 按 type 收集到 Map 中。模板方法在 JdbcTemplate 和 AbstractQueuedSynchronizer 中都有体现。责任链模式在网关过滤器、拦截器中广泛使用。

## Linux 与排查命令

线上 CPU 飙高的排查路径：top 找到进程，top -Hp 找到线程，printf 转十六进制，jstack 抓栈定位热点方法。磁盘满用 du -sh 逐层定位大目录，df -h 确认挂载。网络连通用 telnet 或 nc 验证端口，tcpdump 抓包分析握手细节，ss -s 查看连接概况。

## 编码与安全基础

密码必须用 BCrypt 这类带盐慢哈希存储，不能用 MD5 或 SHA1 裸哈希。SQL 注入的防线是预编译参数绑定，MyBatis 中 # 是占位符、$ 是拼接，$ 只允许用于受控白名单列名。XSS 的防线是输出转义，CSP 作为二层防御。敏感日志输出前必须脱敏。

## 算法基础：数据结构选型

B 树的每个节点既存键也存数据且所有节点都可以参与查询；B+ 树非叶子节点只存键，数据全部在叶子节点且叶子间有链表相连，范围查询更友好。数据库索引和文件系统普遍选择 B+ 树。红黑树是近似平衡二叉搜索树，通过颜色约束保证最长路径不超过最短路径两倍，TreeMap 与 HashMap 的树化桶都用它。

跳表通过多层稀疏链表实现 O(log n) 查找，插入删除只需改指针，Redis 的 zset 和 LevelDB 的 memtable 都用它。布隆过滤器用多个哈希函数和位数组判断元素可能存在或一定不存在，有误判率但无漏判，适合缓存穿透防护与海量数据去重，标准实现不支持删除，计数布隆过滤器可以。

位图用比特位数组标记元素存在性，一亿整数去重只需约 12MB，适合签到、活跃用户统计。RoaringBitmap 把位图分块压缩，是大数据引擎位图索引的通用方案。

LRU 缓存可以用 LinkedHashMap 或手写哈希表加双向链表，get 和 put 都是 O(1)。LFU 按访问频次淘汰，实现上用频次桶加双向链表。

## 算法基础：排序与查找

稳定排序有冒泡、插入、归并、基数；不稳定的有选择、快排、希尔、堆排。工程上 Array.sort 对基本类型用双轴快排，对象用 TimSort。TopK 问题用容量为 K 的小顶堆或快速选择算法，海量数据 TopK 用分治加归并。

二分查找的关键是循环不变量与边界：左闭右开写法中 while left < right，mid 比较后收缩。旋转数组、山脉数组、第一个大于等于目标的下标都是二分的变形，时间复杂度都是 O(log n)。

## 算法基础：海量数据题套路

海量数据题的五板斧：哈希取模分片、分冶归并、位图、堆、外排序。例：100GB URL 文件找 top 10 频率，先按 hash(url) % 1000 拆成小文件，相同 URL 必然落同一文件，每个文件用哈希表统计再取局部 top 10，最后归并全局 top 10。例：40 亿 QQ 号判存在，位图 512MB 搞定。例：两个各 50 亿 URL 的文件求交集，分片后小文件两两比对或用布隆过滤器预筛。

## 系统设计：短链服务

短链服务把长 URL 映射为短码。发号策略有自增 ID 转 62 进制、哈希加冲突检测、预生成号段。自增方案简单但可被遍历，哈希方案长度固定。跳转依靠 301 或 302，301 永久重定向浏览器会缓存导致统计丢失，短链服务通常用 302 以保留点击埋点。高并发读用缓存扛，热点短码加本地缓存。数据量上来后按短码哈希分库分表。

## 系统设计：秒杀系统

秒秒系统的核心是限流、削峰、防超卖。流量入口做答题或验证码削峰，网关层令牌桶限流，商品库存预热进 Redis，用 Lua 脚本原子扣减，扣减成功再发 MQ 异步创建订单。防超卖的关键是库存判断与扣减的原子性，数据库层用 stock > 0 的条件更新兜底。前端按钮置灰、静态化详情页、CDN 分流读流量。

## 系统设计：Feed 流与排行榜

Feed 流的两种模式：推模式把内容写入每个粉丝收件箱，读快写放大；拉模式读时聚合，写轻读重。大 V 场景用推拉结合，普通用户推送、大 V 拉取。收件箱用 Redis list 或 zset 存储，滚动翻页用游标。排行榜用 zset 的 zadd zincrby zrevrange，同分按时间戳排序可以把 score 设计成分数乘以大常数加时间差。

## 系统设计：签到与积分

签到用 Redis 的 setbit 按月建 key，用户每天一个比特位，bitcount 统计当月签到天数，连续签到用位运算从今天往前逐位判断。积分账户要记账流水，每次变动插入流水表再更新余额，对账任务核对流水累计与余额一致。积分过期用延迟消息或定时扫描。

## 系统设计：扫码登录与分布式会话

扫码登录流程：网页生成带唯一 token 的二维码并轮询，手机扫码后带 token 与用户身份请求确认接口，服务端绑定 token 与用户并把状态置为已确认，网页轮询到确认态后换取正式会话。分布式会话用 Redis 集中存储 session 或直接用 JWT 无状态化，JWT 的缺点是签发后无法主动吊销，需要配合黑名单或短有效期加刷新令牌。

## 系统设计：红包与抽奖

红包金额拆分用二倍均值法保证随机且剩余够分，抢红包用 Redis 列表预拆金额，lpop 原子弹出保证不超发。抽奖的中奖概率控制用整体概率法或别名算法，奖品库存扣减同样要原子操作。风控维度包括设备指纹、频次限制和黑名单。

## 微服务与网关

API 网关的职责是路由、鉴权、限流、熔断与灰度。Spring Cloud Gateway 基于谓词与过滤器链，限流过滤器对接 Redis 令牌桶。服务注册发现的心跳与剔除由注册中心完成，Nacos 同时支持配置中心且支持配置灰度发布。链路追踪通过 traceId 串联，跨进程用 HTTP 头或 MQ 属性透传。

## 配置与发布工程

配置中心的选择要点：环境隔离、灰度发布、变更审计与回滚速度。敏感配置要加密存储且密钥与密文分离保管。数据库变更走工单平台评审，大表加字段用 pt-osc 或 gh-ost 在线改表。代码回滚优先于修复，配置回滚优先于代码回滚。

## 测试与质量

单元测试的 FIRST 原则：快速、独立、可重复、自校验、及时。测试金字塔建议单元测试占比七成，接口集成测试两成，端到端一成。Mock 边界依赖而不是 Mock 被测逻辑本身。覆盖率看增量覆盖率更有意义，盲目追求全量覆盖率会导致脆弱测试。

## 性能优化方法论

性能优化的顺序：先测量再优化，先架构后代码，先热点后冷点。常用指标是 QPS、TPS、RT 分位值与错误率。压测要区分基准、容量与稳定性压测，稳定性压测以线上峰值 1.5 倍持续加压观察内存与连接泄漏。优化手段按层次分：架构层读写分离与水平拆分，缓存层多级缓存与预热，应用层异步化批处理与池化，代码层减少序列化与避免大对象拷贝。

## 安全与合规实践

接口安全包含鉴权、签名、时间戳与 nonce 防重放，敏感接口加二次验证。数据安全包含传输 TLS、存储加密与字段级脱敏，手机号展示中间四位打码。日志与告警里不得出现明文密钥与密码，密钥轮换要有灰度期与双读窗口。个人信息的采集与使用需要明示授权并支持删除导出。

## 高频问题速查：并发篇

问：线程安全的本质是什么？答：多线程访问共享可变状态时对读写操作做同步控制，或者直接消除共享状态（不可变对象、栈封闭、ThreadLocal）。

问：读写锁适用什么场景？答：读多写少且读操作耗时，用 ReentrantReadWriteLock 让读并发写互斥；写冲突激烈时用 StampedLock 的乐观读进一步减少开销。

问：线程池提交任务的方法区别？答：execute 无返回值，submit 返回 Future，invokeAll 批量等待，CompletableFuture.supplyAsync 支持回调编排不阻塞调用线程。

问：如何优雅关闭线程池？答：shutdown 拒绝新任务等待存量完成，awaitTermination 设置等待上限，shutdownNow 中断执行中任务并返回未执行队列，钩子脚本里按此顺序组合。

问：虚拟线程适用什么场景？答：高并发阻塞 IO 场景，JDK 21 正式发布，每请求一线程模型回归，CPU 密集任务无收益，且要警惕 pin 与 ThreadLocal 泄漏。

## 高频问题速查：数据库篇

问：为什么推荐自增主键？答：InnoDB 聚簇索引按主键有序，自增 ID 尾部插入避免页分裂；随机主键如 UUID 会导致写放大与碎片。

问：联合索引 (a,b,c) 哪些查询能命中？答：where a、where a and b、where a and b and c 能命中；where b、where c 不能直接命中；范围查询后的列停止匹配。

问：explain 重点看什么？答：type 至少 range 以上，ref 与 eq_ref 较好；rows 估算扫描行数；extra 里 using index 是覆盖索引，using filesort 与 using temporary 需要优化。

问：慢查询治理第一步？答：开启慢日志定位语句，explain 确认执行计划，检查索引与统计信息，再考虑改写 SQL 或加缓存。

问：count 计数怎么优化？答：实时精确计数用计数表加原子更新；近似值用 explain 估算或统计表；大表全量 count 直接避免。

## 高频问题速查：Redis 篇

问：缓存与数据库一致性怎么做？答：主流是旁路缓存加先更新库再删缓存，配合延迟双删或订阅 binlog 的 canal 异步删除，极端一致场景加分布式锁串行化。

问：Redis 为什么快？答：内存操作、单线程无锁竞争、IO 多路复用 epoll、高效数据结构渐进式 rehash 与 listpack 编码。

问：持久化怎么选？答：纯缓存可关持久化；允许分钟级丢失用 RDB；要求秒级安全开 AOF everysec；4.0 之后混合持久化兼顾恢复速度与数据安全。

问：缓存预热与降级？答：预热是上线前把热点 key 提前写入；降级是故障时绕过缓存直接读库或返回默认值，降级开关要放配置中心。

## 高频问题速查：框架篇

问：Spring Bean 默认单例有并发问题吗？答：有，单例 bean 的可变成员变量会被并发共享，应保持无状态或用 ThreadLocal、并发容器。

问：@Transactional 什么时候失效？答：同类内部调用、非 public 方法、异常被吞、异常类型不匹配、多线程内调用，解法分别是走代理、编程式事务、显式回滚与 rollbackFor。

问：BeanFactory 与 ApplicationContext 区别？答：后者继承前者并增加资源加载、事件发布、国际化与自动后处理器注册，日常用的都是 ApplicationContext。

问：MyBatis 缓存级别？答：一级缓存 SqlSession 级默认开启，Spring 集成下每次请求新会话基本失效；二级缓存 namespace 级，多表关联下容易脏读，生产建议用 Redis 外置缓存。

## 高频问题速查：分布式篇

问：接口幂等怎么保证？答：唯一索引兜底、token 预申请、状态机流转约束、乐观锁版本号，按业务语义选型，重试场景必须幂等。

问：分布式锁的选型？答：Redis 锁性能高适合高并发短临界区，Redison 看门狗解决续期；ZooKeeper 锁可靠性强适合强一致场景；fencing token 防止过期后误写。

问：接口超时与重试的默认值？答：超时要小于调用方整体预算并留重试余量；重试只用于幂等接口，次数两到三次并加指数退避与抖动，避免重试风暴。

问：灰度发布怎么做？答：按流量比例、用户标签、地域或机器批次逐步放量，观察核心指标自动决定推进或回滚，灰度期间新老版本接口要兼容。

## 场景题清单：线上问题排查

CPU 100%：定位进程、定位线程、抓栈找热点。内存泄漏：对比多次堆快照的支配树增长。OOM 杀进程：区分堆内与堆外，检查容器内存限制与 JVM 参数配比。接口突然变慢：先看监控是全量还是局部，检查依赖服务、数据库慢查询、GC 停顿与线程池饱和度。消息堆积：先扩容消费、再查慢消费、必要时跳过可重放消息。缓存命中率暴跌：排查热 key 失效、批量过期与发布变更导致的 key 结构变化。

## 场景题清单：容量与预算

估算 QPS：日请求量除以 86400 再乘峰值系数，电商峰值系数一般取 3 到 10。数据库容量：单表超过五百万行考虑分表，单库 QPS 超过五千考虑读写分离或分库。带宽估算：平均响应体大小乘 QPS 得下行带宽，预留三成余量。成本优化顺序：缩容低负载服务、竞价实例跑离线任务、存储生命周期归档、按量转包年包月。

## 场景题清单：数据迁移

异构数据库迁移步骤：全量迁移加增量同步加数据校验加双读灰度加切写回滚预案。全量用离线任务分批导出，增量用 binlog 订阅。校验用抽样对比加全量 checksum。切换选择低峰期，保留反向同步一周以上以支持快速回滚。

## 操作系统要点：进程与内存

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。进程上下文切换需要切换页表与内核栈，线程切换只切换寄存器与栈指针，代价更小。协程切换完全在用户态完成。进程间通信方式有管道、消息队列、共享内存、信号量、信号与 socket，共享内存最快但需要信号量同步。

虚拟内存通过页表把虚拟地址映射到物理地址，多级页表节省页表内存，TLB 缓存页表项加速翻译。缺页中断把数据从交换分区调入。页面置换算法有 FIFO、LRU、Clock 时钟算法，内核实际多用近似 LRU 的双链表活跃与非活跃队列。

内存分配：brk 处理小堆块，mmap 处理大块与文件映射。内存泄漏在用户态表现为 RSS 持续增长不回落，容器环境要区分 cgroup OOM 与 JVM 堆 OOM。

## 操作系统要点：IO 模型

五种 IO 模型：阻塞、非阻塞、IO 多路复用、信号驱动、异步。select 用固定位图上限 1024，poll 链表无上限但都要线性扫描，epoll 用红黑树加就绪链表，事件驱动复杂度 O(1)，是 Linux 高并发网络的基石。Reactor 模式分单 Reactor 单线程、单 Reactor 多线程与主从 Reactor，Netty 是主从 Reactor 加 Worker 线程组的实现。

零拷贝的三种途径：mmap 加 write 减少一次拷贝；sendfile 直接在内核态转发；带有 scatter gather 的 sendfile 连内核内拷贝都省。Kafka 与 RocketMQ 的顺序写加零拷贝是高吞吐的两大支柱。

## 计算机网络真题汇总

问：浏览器输入网址后发生了什么？答：DNS 解析、TCP 握手、TLS 握手、HTTP 请求、服务端处理、渲染。每个环节都可以深挖，CDN 命中与缓存控制是前端性能关键。

问：GET 与 POST 的区别？答：语义上 GET 幂等获取 POST 提交，长度限制来自浏览器与服务器实现而非协议，GET 也能带 body 但不应被依赖。

问：Cookie 与 Token 的取舍？答：Cookie 自动携带但受同源策略约束，Token 手动携带适合跨端与微服务，敏感操作都要防 CSRF 与 XSS。

问：长连接如何保活？答：TCP keepalive 探测、应用层心跳、读写空闲检测三件套，网关与负载均衡的空闲超时必须小于心跳间隔。

问：跨域的解法？答：CORS 预检加响应头是标准方案，开发环境用代理，生产环境的第三方回调用 JSONP 已过时。

## 代码质量实践清单

命名：方法名是动词短语，布尔用 is 或 has 前缀，避免 data、info 这类空泛词。函数：一屏内读完，参数不超过四个，超过封装对象；提前返回减少嵌套。注释：解释为什么而不是是什么，公共 API 写契约。异常：业务异常语义化错误码，禁止捕获后静默，禁止用异常做流程控制。日志：关键链路有 traceId，级别语义清晰，禁止字符串拼接占位符误用。

重构手法清单：提取方法消长函数，提取类消大类，以查询代替临时变量，卫语句消嵌套，多态代替条件表达式，引入参数对象消长参数列表。重构的前提是测试覆盖保护，小步提交随时可停。

## 每日一题归档：第 1 到 15 题

第 1 题讲 String 为什么设计成不可变：字符串常量池共享、线程安全、hashCode 缓存。第 2 题讲 Integer 缓存池：-128 到 127 自动装箱复用对象，超过范围比较必须用 equals。第 3 题讲 == 与 equals 与 hashcode 的契约：重写 equals 必须重写 hashcode，否则哈希容器行为异常。第 4 题讲 finalize 为什么废弃：执行时机不确定且影响 GC，替代是 Cleaner 与显式 close。第 5 题讲 SPI 机制：META-INF/services 目录注册实现，配合线程上下文类加载器打破双亲委派。第 6 题讲注解的保留策略：SOURCE 编译期丢弃、CLASS 进字节码运行时不可见、RUNTIME 反射可读。第 7 题讲泛型擦除：编译后 Object 替换与桥方法，不能泛型数组与 instanceof 泛型。第 8 题讲反射性能：Method 查找与装箱开销，缓存 Method 与 MethodHandle 改善。第 9 题讲 Java 版本演进要点：8 的 lambda 与 stream，11 的 httpclient 与 var，17 的 sealed 与 record，21 的虚拟线程与模式匹配。第 10 题讲 stream 的短路操作：findAny 与 limit 与 anyMatch，无限流必须有短路。第 11 题讲 CompletableFuture 异常传播：exceptionally 处理、whenComplete 透传、handle 转换。第 12 题讲 Optional 的正确用法：返回值语义而非字段或参数，禁止 get 裸调与 isPresent 加 get 组合。第 13 题讲日期时间 API：LocalDateTime 无时区、ZonedDateTime 带时区、Instant 是时间戳，格式化用 DateTimeFormatter 线程安全。第 14 题讲 BigDecimal 的坑：构造用字符串，比较用 compareTo，等值判断 scale 敏感。第 15 题讲序列化的风险：反序列化漏洞、版本兼容，优先 JSON 或 protobuf。

## 每日一题归档：第 16 到 30 题

第 16 题讲 G1 与 CMS 的区别：G1 可预测停顿、Region 化整理无碎片、并发标记周期不同。第 17 题讲对象一定分配在堆上吗：逃逸分析后标量替换可栈分配，但 HotSpot 实际以标量替换为主。第 18 题讲 JIT 分层编译：C1 快速编译收集 profile，C2 依据 profile 深度优化，热点探测靠方法调用计数与回边计数。第 19 题讲三色标记与漏标：CMS 用增量更新，G1 用原始快照 SATB，都是解决并发标记的对象消失问题。第 20 题讲 DirectByteBuffer 的回收：Cleaner 机制关联堆外内存，堆内引用释放后触发堆外回收，-XX:MaxDirectMemorySize 限容。第 21 题讲线程优先级：语义弱且依赖操作系统调度器，不要依赖优先级设计业务正确性。第 22 题讲 ForkJoinPool 的 work-stealing：每个工作线程双端队列，自己 LIFO 执行、窃取者 FIFO。第 23 题讲线程安全的单例五种写法：饿汉、静态内部类、枚举、双重检查锁、CAS 自旋。第 24 题讲 ReadWriteLock 的饥饿写问题：写线程可能一直排队，公平模式缓解但吞吐下降。第 25 题讲 ThreadLocal 在线程池的清理时机：任务结束手动 remove，拦截器 afterCompletion 或 try finally 包裹。第 26 题讲 happens-before 规则：程序顺序、监视器锁、volatile、线程启动与终止、传递性，并发正确性的推理基础。第 27 题讲 ABA 的工程案例：无锁栈与并发映射的版本号防护。第 28 题讲异步 IO 在 Java 的现状：AIO 在 Linux 的实现退化为 epoll 模拟，Netty 放弃 AIO。第 29 题讲 Thread 的 interrupt 语义：协作式中断标志，阻塞方法抛 InterruptedException 并清标志，捕获后要恢复中断或终止。第 30 题讲 Structured Concurrency：结构化并发把子任务生命周期绑定作用域，JDK 21 预览，虚拟线程的最佳搭档。

## 框架源码追问：Spring 篇

问：refresh 流程做了什么？答：十二步里关键是准备 bean 工厂、执行 bean 工厂后处理器、注册 bean 后处理器、初始化消息源与事件派发器、创建内建 bean、注册监听器、实例化单例、发布刷新完成事件。

问：三级缓存为什么需要工厂而不是直接放对象？答：为了在需要 AOP 代理时才创建代理，未发生循环依赖就保持原生对象，保证代理语义与初始化顺序的最小侵入。

问：@Autowired 与 @Resource 区别？答：前者按类型优先 byType 再 byName，后者 JSR 规范按名称优先，配 @Primary 与 @Qualifier 解决多候选。

问：事件监听在事务的哪个阶段执行？答：普通 @EventListener 在发布点同步执行，@TransactionalEventListener 可绑定 AFTER_COMMIT 等事务阶段，适合事务提交后的副作用。

问：Bean 的销毁顺序？答：容器 close 触发，先销毁依赖最少的，DisposableBean 的 destroy 与 destroyMethod 与 @PreConstruct 对应的销毁注解按序执行。

## 框架源码追问：MyBatis 与 ORM 篇

问：Mapper 接口为什么能直接调用？答：JDK 动态代理拦截接口方法，MapperMethod 封装 SQL 元数据与执行，命名空间绑定接口全限定名。

问：动态 SQL 的原理？答：SqlNode 树在解析期构建，运行期按参数求值拼接，where 与 set 节点负责修剪前导逗号与连接符。

问：批量插入怎么做最快？答：foreach 拼多值 insert 受 SQL 长度与参数上限约束，分批五百到一千条，或用 rewriteBatchedStatements 的 JDBC 批处理。

问：懒加载的实现？答：代理对象在访问属性时触发附加查询，fetchType 按需配置，注意 N 加一问题用 resultMap 嵌套查询或 join 一次性取。

## 运维部署问答

问：JVM 容器参数怎么配？答：用 -XX:MaxRAMPercentage 按容器内存百分比配置，堆外内存与线程栈预留三成，Java 10 加上 UseContainerSupport 自动感知 cgroup 限制。

问：滚动发布与蓝绿发布的取舍？答：滚动省资源但新老共存时间长需要双向兼容；蓝绿切流快回滚快但双倍资源；数据库结构变更都要向后兼容先行。

问：健康检查怎么分级？答：liveness 判断进程要不要重启，readiness 判断要不要接流量，两者分离避免抖动放大；依赖服务的健康不应计入自身 liveness 防止级联重启。

问：日志采集链路？答：应用输出 JSON 到 stdout 与文件，Filebeat 或 Vector 采集到 Kafka，消费进 Loki 或 ES，告警规则基于日志关键字与频次。

## 数据库真题：索引与优化

问：什么情况下索引失效？答：对索引列做函数或运算、隐式类型转换、前导模糊匹配 like 百分号开头、or 两侧存在无索引列、优化器评估回表成本高于全表扫描。

问：force index 什么时候用？答：统计信息偏差导致执行计划选错时的应急手段，长期方案是修正统计信息或改写 SQL，索引提示要写注释说明原因与清理时间。

问：在线加索引会锁表吗？答：MySQL 5.6 之后 DDL 支持 online，加索引期间允许并发 DML，短暂阻塞发生在开始与结束元数据锁阶段，大表仍建议低峰执行。

问：唯一索引与普通索引的写入差异？答：唯一索引需要检查冲突，change buffer 对唯一索引不可用，写多读少场景普通索引加业务校验的组合吞吐更好。

问：自增主键用完了怎么办？答：int 上限约 21 亿，提前规划迁移到 bigint，分库分表场景在位段设计时预留类型升级路径。

## 中间件运维问答

问：网关 499 日志说明什么？答：客户端主动断连，常见是上游处理超过客户端超时，排查方向是应用耗时与客户端超时配置的差值。

问：502 与 504 的区别？答：502 是上游返回无效响应或连接被拒，504 是上游超时未响应，一个看进程存活一个看处理耗时。

问：如何给服务做容量画像？答：压测得到单实例容量上限，结合峰值 QPS 与冗余系数算实例数，按大促日历提前扩容，常态用弹性伸缩跟随曲线。

## 线程池生产实践

线程池上线前的检查项：队列必须有界防止 OOM，拒绝策略必须可观测，核心参数必须可配置而不是硬编码。生产环境建议使用自定义拒绝策略配合监控告警，而不是默认的 AbortPolicy；自定义策略里至少要做三件事：记录被拒绝任务上下文、递增监控计数器、按业务决定是降级执行还是快速失败返回。

线程池运行时的观测指标：活跃线程数、队列长度、已完成任务数、拒绝次数，四个指标接监控大盘。队列长度持续超过容量八成就要评估扩容或异步化，等拒绝发生再处理已经晚了。

## 集合生产实践

HashMap 树化的完整条件必须同时满足两个阈值：当链表长度超过 8 且数组容量达到 64 时，链表转换为红黑树；只满足链表长度而容量不足时优先扩容而不是树化。树化后退化的条件是红黑树节点数收缩到 6 时退化回链表，两个阈值差用于抑制在边界附近反复转换的抖动。

集合选型的实践建议：默认 ArrayList 与 HashMap，需要有序用 LinkedHashMap，需要排序用 TreeMap 或 PriorityQueue，并发场景用 CopyOnWriteArrayList 与 ConcurrentHashMap，队列用 ArrayDeque 与 LinkedBlockingQueue。禁止在循环里对集合做结构性修改，禁止把集合当参数到处传可变引用。

## JVM 生产实践

对象进入老年代的两条路径：大对象直接进入老年代，可通过 `-XX:PretenureSizeThreshold` 控制阈值，避免大对象在新生代来回复制；普通对象经历多次 Minor GC 仍存活则通过年龄晋升机制进入老年代，默认晋升年龄是 15，可通过 `-XX:MaxTenuringThreshold` 调整。

堆参数实践：初始堆与最大堆设成一样避免动态扩容抖动；选择 G1 时 Region 大小按大对象体积评估；容器环境用百分比参数；任何 JVM 参数变更都要附带 GC 日志对比数据。
